**Upgrade:** `codex/product-ux-audit`. **PR baseline:** `origin/master` at `d72204d18223dd93717a6ffa310b63b58eeb0afc`. `origin/main` pointed to that same commit when fetched. The initial takeover began at `b809f9a72393a2f1b01549997d18fcd54c716be4`; account/login/onboarding and personal-profile changes arrived upstream afterward and were integrated. ## Backend: fixes that are harder to see in a screenshot

| Claim | Earlier problem | Upgrade and evidence pointer |
| --- | --- | --- |
| B1: No invented successful report on provider failure | Missing AI configuration produced unrelated canned sermon content; provider failure handling could appear successful. | Durable failed run with recoverable error, preserving source and previous good revisions. No universal hardcoded fallback-model assumption. `backend/app/report_processing/engine.py`; `tests/test_report_processing.py`, `tests/test_review_integrity.py`. |
| B2: Validate before persistence | Invalid shape/types, blank content or failed quality flags could pass through; a word-count threshold could reject legitimate short reports. | Provider schema plus local validation of required title/text, shape/types and quality constraints across consolidated and sibling generators. Brief valid drafts remain allowed. `app/services/gemini_gateway.py`, reporting/editing/proofreading providers and schema tests. This is not semantic accuracy certification. |
| B3: Revision-bound approval and export | Generated output could become final/exportable without genuine human review, and later source/revision changes could leave stale approval. | Draft and approved states are separate; approval records identify the exact current revision. Source/editor/proofreader changes revoke current export permission while history remains. Exports render the approved saved text/metadata, preventing same-filename reuse across sessions. `app/database/final_report_repo.py`, `review_integrity.py`, review/export routers; `tests/test_review_integrity.py`. |
| B4: Preserve original sources | Ordinary deletion could remove original audio and session history; repeated initialization/indexing could overwrite established text/linkage. | Archive/restore retains files, raw text and revisions; recording deletion refuses original removal. Active/archive filters remain account scoped. Existing initialization is idempotent and rejects account rebinding. Tests compare synthetic bytes and saved rows. `app/database/session_repo.py`, `app/audio/router.py`, `app/sessions/router.py`. Previously deleted files are not recovered. |
| B5: Generation uses the source it actually consumed | Source changes during the awaited AI response could stamp source B onto content generated from source A. | Capture inputs in one read snapshot; preserve actual prompt/input hashes and selected revision identities. Compare under a SQLite write lock, then atomically save editor draft, final draft, result and session pointers. Changed source causes recoverable failure; previous work remains. `tests/test_generation_provenance.py` plus production snapshot/transaction code. |
| B6: Atomic accepted-proofread finalization | A later conflict/fault could return failure after replacing the previously active report or approval history. | Source validation, draft replacement and approval share one SQLite write transaction. Conflicts/faults roll everything back; repeated same-source requests are idempotent. Reviewed proofread title is authoritative unless deliberately overridden. `tests/test_atomic_finalization.py`, `app/database/final_report_repo.py`. Cloud isolation fails closed where required transaction semantics cannot be verified. |
| B7: Honest domain/provider readiness | A missing generated KJV database broke tests; readiness did not adequately separate configuration from real provider success. | Offline reproducible full verse build, source hashes/counts/completeness and a readiness endpoint. All 66 books/31,102 verses are present; proper-name coverage is explicitly partial. Provider configured does not mean live verified. `scripts/build_kjv_database.py`, `app/services/bible_context_service.py`, `app/main.py`. |
| B8: Preserve upstream account boundaries while integrating review | Newly added approval/archive routes and inherited sibling review/run routes needed ownership guards when combined with upstream auth. | Review-stage routers require a valid onboarded account and session ownership. Foreign-account approval/read/download/archive/restore are rejected; processing cancel/result checks owning session. `app/auth/dependencies.py`, review/run routers, `tests/test_upgrade_account_boundaries.py`. This is bounded protection, not comprehensive whole-app multi-account isolation. |

Auto-continue-to-proofreading defaults OFF. Consolidated generation creates reviewable drafts; it does not auto-launch the separate proofreader. A provider migration, newer transcription adapter, statement-level AI evidence links or new analytics were not added. This branch improves workflow integrity and usability; it does not prove higher real-audio transcription quality.

## Remaining limitations and acceptance work

1. **Production security is not complete.** Upstream capture WebSocket, recorded-upload/transcription/media routes and shared settings/standards have remaining account authorization/ownership gaps. In particular, capture/session creation can still fall back to the legacy account, and media access is not comprehensively isolated. These are inherited issues, not repaired by changing UI fetch headers. No production deployment or comprehensive account-isolation claim is justified. The PR is a private draft for review; production authorization and capture account binding require separate engineering acceptance before merging for release.
2. **Real services/devices were not exercised.** No actual microphone/USB capture continuity, long service recording, YouTube provider, paid AI call, live Supabase account flow, cloud database or production deployment was tested. Browser UI fixtures do not prove those lifecycles; SQLite transaction tests do not prove Azure SQL support. The critical integrity operations deliberately fail closed for unsupported isolation.
3. **Domain names remain partial.** `names.tsv` is absent. The build includes 101 canonical/book supplement entries, not the recorded 2,808-name corpus. Proper-name recognition quality must not be inferred from complete verses.
4. **Design and performance still need judgement.** Sampled text/control contrast passed, but this is not whole-app accessibility certification. Legacy CSS and bundle size remain substantial; lint warnings remain. Inspect long real-world reading tasks, keyboard/screen-reader use and low-powered machines before acceptance.

## How to evaluate differences honestly

Use the same commits, synthetic inputs, viewports and test scenarios on both branches. Record whether each item was independently found, missed but subsequently verified, unsupported, disagreed or untested. Give file/line or reproducible behavior evidence. A screenshot can establish composition, not transaction atomicity; a passing mocked test cannot establish real-provider quality. A single comparison cannot establish that one AI system is generally more capable than another.

The branch contains significant design and trust-workflow improvements supported by local evidence. Final visual acceptance, remaining production boundaries and real-device/service acceptance belong to the human review, not this document.
